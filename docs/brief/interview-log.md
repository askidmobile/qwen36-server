# Interview log — Qwen3.6 27B inference server

## 2026-08-07 — первая сессия

### Исходный бриф (brain dump, дословно по сути)

> Нужно собрать и сделать инференс модели Qwen3.6 27b на 2bit (https://huggingface.co/unsloth/Qwen3.6-27B-GGUF) со всеми нашими разработками в части candle:
> `/Volumes/Askid Dev/Projects/candle-fork`, `/Volumes/Askid Dev/Projects/candle-fork-qwen35-batch`, `/Volumes/Askid Dev/Projects/Qwen3.5 4b`.
> Создать полноценный интерфейс для работы с моделью через Chat Completion API (OpenAI Comp), Response API (OpenAI), Message API (Anthropic). Доступ по API KEY.
> Стек — RUST. Запуск — Windows в первую очередь. Тестовая машина: yttri-win (192.168.2.89), работать на диске D: (на C: нет места), RTX 3060 12 GB.
> Веб-чат в браузере: указывать API KEY, чат с моделью, показ скорости генерации в токенах, наполнение контекстного окна и т.п.
> GET /v1/models — информация о модели и её настройках.
> Стартовое контекстное окно 81K (рекомендуется Qwen). Остальные режимы/настройки — с Hugging Face.
> Модель должна работать в 4 потока — на Qwen3.5 4B это уже сделано.

Позже добавлено: «наши разработки лучше llama.cpp, так что мы должны делать сами» — llama.cpp только как эталон для parity-замеров, не как компонент.

### Q&A (выбор режима)

**Q: Режим интервью?** → Интервью — по одному вопросу, максимальная глубина.

### C5/C10 — Квант

**Q: Какой 2-bit квант целевой?** (контекст: Q2_K_XL ядра есть; IQ2_XXS/IQ2_M нужны новые ядра)
→ **Старт с Q2_K_XL (быстрая валидация), затем IQ2 ядра как фаза 2.**

### C5 — Vision

**Q: Vision-энкодер (картинки/видео)?**
→ **Text-only**: API принимает только текст; картинки в запросах — ошибка 400.

### C9 — API-ключи

**Q: Устройство ключей?**
→ **Один мастер-ключ из конфига/env**; веб-чат спрашивает один раз, хранит в localStorage.

### C9 — Поверхность атаки

**Q: Куда слушает сервер, кто пользователи?**
→ **LAN-only**: 0.0.0.0 в домашней сети; пользователь + yttri-win; HTTP без TLS.

### C8 — Нагрузка

**Q: Сколько одновременных клиентов?**
→ **4 одновременных клиента — ключевая фича**, сразу через batch-планировщик (из qwen35-batch, 4 слота).

### C11 — Критерии успеха

**Q: Измеримые критерии готовности сервера?** (multi-select)
→ **Только стабильность: 4 слота × длинные генерации (8-16K токенов) без падений и утечек VRAM.**

**Q (уточнение): Скорость и API-совместимость — критерии?**
→ **Нет**: только стабильность 4 слотов; остальное — вехи, не критерии.

### C5 — Веб-чат

**Q: Что в веб-чате помимо ключа/стрима/скорости?** (multi-select)
→ **Все пункты**: прогресс-бар контекста (N/81K), отображение thinking сворачиваемыми блоками, переключатель thinking/non-thinking, настройки сэмплинга, история чатов в браузере.

### C10 — Расположение кода

**Q: Где живёт код сервера?**
→ **В папке «Qwen3.6 27B»** — standalone крейт с path-зависимостью на форк (candle-fork-qwen35-batch).

### C10 — Платформы

**Q: Обязательные платформы v1?**
→ **Windows+CUDA (yttri-win) первично; macOS+Metal для разработки; CPU fallback.**

### C5 — Responses API

**Q: Глубина Responses API в v1?**
→ **Базовый**: POST /v1/responses, input → output текст, streaming SSE, store=false.

### C5 — Tools

**Q: Function calling в Chat Completions и Messages API?**
→ **Да, в обоих**: tools + tool_choice, парсинг tool_calls из вывода модели.

### C6 — Данные/хранение

**Q: Что хранить на диске помимо модели?**
→ **Ничего**: логи сервера в stdout; чаты живут в браузере (localStorage).

### C5 — /v1/models

**Q: Состав ответа GET /v1/models?**
→ **OpenAI-совместимый минимум (id, object, created, owned_by) + расширение: контекст, квант, слоты, режимы.**

### C5 — Сэмплинг-пресеты

**Q: Параметры в пресетах UI?**
→ **Полный набор**: temperature, top_p, top_k, min_p, presence_penalty, repetition_penalty, max_tokens.

### C5 — Поведение при переполнении контекста

**Q: Лимиты запросов?**
→ **Авто-обрезка старых сообщений при переполнении (sliding window).**

**Q (уточнение): Как обрезать?**
→ **System-промпт всегда сохраняется; обрезаются самые старые user/assistant пары; метка `truncated: true` в ответе.**

### C10 — Сборка на Windows

**Q: UX сборки/запуска на Windows?**
→ **Cargo build из исходников на yttri-win** (тулчейн для candle там уже есть).

### C12 — Риски

**Q: Топ-риски?** (multi-select)
→ **Качество 2-bit окажется неприемлемым — перейти на 3-bit/4-bit.**
(Остальные риски из меню явно отвергнуты как главные: сложность IQ2, нехватка VRAM, стоимость API-совместимости.)

### Roadmap

**Q: Порядок работ v1?**
→ **Сперва Q2_K_XL text-only single-slot → API + веб-чат → потом 4 слота → IQ2.**
