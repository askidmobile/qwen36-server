# RESEARCH: sampling, defaults, reasoning, tools

Проверено по официальным документам и официальным репозиториям на 2026-08-30. Блоги/Reddit не использовались. «Не найдено» ниже означает: в просмотренных официальных docs/source не найдено; это не доказательство отсутствия закрытой/недокументированной настройки.

| Продукт | 1. API request: какие sampling/max/seed поля клиент может менять | 2. Defaults / presets / priority | 3. Reasoning / thinking | 4. Server-side sampling lock | 5. Tools vs inference sampling |

| Ollama | Native `/api/generate` и `/api/chat`: request имеет `options`, которые ссылаются на Modelfile-параметры; документированные параметры включают `temperature`, `top_p`, `top_k`, `min_p`, `repeat_penalty`, `seed`, `num_predict`, `stop` ([API generate/chat](https://github.com/ollama/ollama/blob/main/docs/api.md#generate-a-completion), [Modelfile valid parameters](https://github.com/ollama/ollama/blob/main/docs/modelfile.mdx#valid-parameters-and-values)). Официальный source `api.Options` также содержит `presence_penalty` и `frequency_penalty` как runtime JSON-поля ([api/types.go](https://github.com/ollama/ollama/blob/main/api/types.go#L568-L585)). OpenAI-compatible `/v1/chat/completions`: документированы `frequency_penalty`, `presence_penalty`, `seed`, `temperature`, `top_p`, `max_tokens`, `stop`, `tools`, но не `top_k`, `min_p`, `repeat_penalty`; `tool_choice` отмечен unsupported ([openai compatibility](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx#L179-L214)). | Есть code defaults (`temperature=0.8`, `top_k=40`, `top_p=0.9`, `repeat_penalty=1.0`, `num_predict=-1`, penalties `0.0`) в `DefaultOptions` ([api/types.go](https://github.com/ollama/ollama/blob/main/api/types.go#L1104-L1122)); Modelfile `PARAMETER` задаёт model defaults ([Modelfile](https://github.com/ollama/ollama/blob/main/docs/modelfile.mdx#valid-parameters-and-values)). Порядок в source: `DefaultOptions()` → `model.Options` → `requestOpts`, то есть request overrides model defaults ([server/routes.go](https://github.com/ollama/ollama/blob/main/server/routes.go#L129-L148)). | Отдельный механизм, не sampling: native API имеет поле `think` boolean или level `low|medium|high|max`; ответ разделяет trace в `message.thinking`/`thinking` и финальный текст в `message.content`/`response` ([Thinking docs](https://github.com/ollama/ollama/blob/main/docs/capabilities/thinking.mdx#L17-L23), [API chat params](https://github.com/ollama/ollama/blob/main/docs/api.md#generate-a-chat-completion)). OpenAI-compatible docs поддерживают `reasoning_effort` и `reasoning.effort` ([openai compatibility](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx#L187-L213)). | Официального server-side запрета клиентских sampling overrides не найдено. Напротив, официальный source применяет `requestOpts` после `model.Options` ([server/routes.go](https://github.com/ollama/ollama/blob/main/server/routes.go#L129-L148)). | `/api/chat` принимает `tools` и возвращает `message.tool_calls`; examples выполняют функцию в клиентском коде, добавляют tool result в `messages` и делают follow-up request ([Tool calling docs](https://github.com/ollama/ollama/blob/main/docs/capabilities/tool-calling.mdx#L1-L10), [пример client loop](https://github.com/ollama/ollama/blob/main/docs/capabilities/tool-calling.mdx#L93-L107)). Следовательно breaker повторяющихся tool calls должен жить в клиентском agent loop / wrapper, а не в sampler Ollama. |
| LM Studio | OpenAI-compatible `/v1/chat/completions`: docs прямо говорят передавать inference parameters в payload и перечисляют `top_p`, `top_k`, `temperature`, `max_tokens`, `stop`, `presence_penalty`, `frequency_penalty`, `logit_bias`, `repeat_penalty`, `seed`; `min_p` в этом списке не найден ([Chat Completions docs](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)). LM Studio REST `/api/v1/chat`: документированы `temperature`, `top_p`, `top_k`, `min_p`, `repeat_penalty`, `max_output_tokens`, но в просмотренной REST-странице не найдены `seed`, `presence_penalty`, `frequency_penalty` ([REST chat docs](https://lmstudio.ai/docs/developer/rest/chat)). SDK prediction config документирует `maxTokens`, `temperature`, `topKSampling`, `topPSampling`, `minPSampling`, `repeatPenalty`; `seed`, presence/frequency penalties в этой странице не найдены ([Python config](https://lmstudio.ai/docs/python/llm-prediction/parameters), [TS `LLMPredictionConfigInput`](https://lmstudio.ai/docs/typescript/api-reference/llm-prediction-config-input)). | Есть несколько уровней defaults/presets. `model.yaml` может “bake in” operation/runtime defaults, включая `llm.prediction.topKSampling`, `llm.prediction.temperature`, `llm.prediction.minPSampling`, и load options ([model.yaml](https://lmstudio.ai/docs/app/modelyaml)). Config Presets сохраняют system prompt и Advanced Configuration параметры, например Temperature/Top P/Max Tokens; новые presets не включают load parameters, для load defaults рекомендуются per-model defaults ([Presets](https://lmstudio.ai/docs/app/presets)). Per-model defaults применяются при загрузке модели ([Per-model defaults](https://lmstudio.ai/docs/app/advanced/per-model)). SDK docs отделяют inference-time per-request parameters от load-time parameters; load config игнорируется, если модель уже загружена ([Python config](https://lmstudio.ai/docs/python/llm-prediction/parameters)). **Не подтверждено:** в официальных docs не найден полный формальный priority chain для конфликтов `model.yaml` vs per-model defaults vs selected preset vs API request. | Отдельный механизм, не sampling. REST `/api/v1/chat` имеет поле `reasoning: "off"|"low"|"medium"|"high"|"on"`; docs говорят, что будет error, если модель не поддерживает выбранный reasoning, и default выбирается автоматически для модели ([REST chat](https://lmstudio.ai/docs/developer/rest/chat)). OpenAI-compatible Responses поддерживает `reasoning: {"effort":"low"}` ([Responses docs](https://lmstudio.ai/docs/developer/openai-compat/responses)). `model.yaml` может объявлять `reasoning: true` и custom field `enableThinking`, который выставляет Jinja variable `enable_thinking` ([model.yaml](https://lmstudio.ai/docs/app/modelyaml)). | Официального server-side запрета клиентских sampling overrides не найдено. Server Settings docs описывают port/network/auth/MCP switches, а не sampling lock ([Server Settings](https://lmstudio.ai/docs/developer/core/server/settings)). | OpenAI-compatible tool use docs явно разделяют: LLM выводит запрос функции, ваш код выполняет функцию, ваш код возвращает result в историю ([Tool Use docs](https://lmstudio.ai/docs/developer/openai-compat/tools)). REST `/api/v1/chat` может включать integrations / MCP и возвращать `tool_call` с `output` или `invalid_tool_call`, то есть там loop частично живёт в REST/integration layer ([REST chat](https://lmstudio.ai/docs/developer/rest/chat)). Python SDK `.act()` — отдельный automatic multi-round tool calling API с “execution rounds” и callbacks по раундам ([Python `.act()`](https://lmstudio.ai/docs/python/agent/act)). Breaker повторов должен жить в этом agent/integration layer или в вызывающем приложении, не в sampling-параметрах. |
| vLLM | OpenAI Chat Completions source содержит стандартные поля `frequency_penalty`, `presence_penalty`, `seed`, `temperature`, `top_p`, `max_tokens`/`max_completion_tokens`, `stop`, `tools`, `reasoning_effort` и extra sampling `top_k`, `min_p`, `repetition_penalty`, `length_penalty`, `stop_token_ids`, `min_tokens`, etc. ([chat protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/chat_completion/protocol.py#L213-L301)). OpenAI Completions source аналогично содержит `temperature`, `top_p`, `seed`, `max_tokens`, presence/frequency penalties и extra `top_k`, `min_p`, `repetition_penalty` ([completion protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/completion/protocol.py#L46-L110)). Responses source содержит `temperature`, `top_p`, `top_k`, `max_output_tokens`, `presence_penalty`, `frequency_penalty`, `repetition_penalty`, `seed`, `stop`; `min_p` в Responses protocol не найден ([responses protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/responses/protocol.py#L136-L184), [extra response fields](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/responses/protocol.py#L280-L286)). Docs также показывают extra_body для non-OpenAI params вроде `top_k` ([OpenAI-compatible server](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)). | `SamplingParams` neutral defaults: `temperature=1.0`, `top_p=1.0`, `top_k=0`, `min_p=0.0`, `repetition_penalty=1.0`, `max_tokens=16` ([sampling_params.py](https://github.com/vllm-project/vllm/blob/main/vllm/sampling_params.py#L215-L279)). По умолчанию `--generation-config auto`: vLLM грузит Hugging Face `generation_config.json` из model path, если он есть; `--generation-config vllm` отключает это и использует vLLM defaults; path к generation config тоже поддержан ([OpenAI-compatible server note](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/), [engine args](https://docs.vllm.ai/en/latest/configuration/engine_args/#generation-config), [ModelConfig source](https://github.com/vllm-project/vllm/blob/main/vllm/config/model.py#L326-L336)). `--override-generation-config` merge/set поверх выбранного generation_config ([engine args](https://docs.vllm.ai/en/latest/configuration/engine_args/#override-generation-config)). Source `get_diff_sampling_param()` берёт из generation config только `repetition_penalty`, `temperature`, `top_k`, `top_p`, `min_p`, `max_new_tokens` и мапит `max_new_tokens` → `max_tokens` ([model.py](https://github.com/vllm-project/vllm/blob/main/vllm/config/model.py#L1715-L1767)). Request wins для явно заданных sampling fields: `to_sampling_params()` использует request value, если оно не `None`, иначе `default_sampling_params`, иначе neutral default ([chat protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/chat_completion/protocol.py#L662-L750)). `max_tokens` дополнительно ограничивается context/model/platform/server caps через `get_max_tokens()` ([api_utils.py](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/serve/utils/api_utils.py#L169-L205)). | Отдельный механизм, не sampling. Для extraction нужен `--reasoning-parser`; output имеет отдельное поле `reasoning` ([Reasoning Outputs](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)). Для моделей с template-переключателем thinking docs используют `chat_template_kwargs`, server defaults через `--default-chat-template-kwargs`, и request-level `chat_template_kwargs` имеют приоритет над server defaults ([Reasoning Outputs: server defaults/request override](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)). `reasoning_effort` в Chat Completions и `reasoning.effort` в Responses автоматически инжектят `enable_thinking` для моделей, которым это нужно; explicit `chat_template_kwargs.enable_thinking` имеет приоритет ([Reasoning Outputs: automatic enable_thinking](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)). `thinking_token_budget` — per-request лимит reasoning tokens, отдельный от обычного sampling, хотя технически передаётся в `SamplingParams` ([Reasoning Outputs: thinking budget](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)). | Официального “запретить клиенту менять sampling” не найдено. `--generation-config`/`--override-generation-config` задают defaults/caps, но source request path всё равно применяет request values when present ([chat protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/chat_completion/protocol.py#L662-L750)). Исключение по смыслу — resource/server caps на output length (`max_new_tokens`, context, platform) через `get_max_tokens`, это не общий lock temperature/top_p/etc. ([api_utils.py](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/serve/utils/api_utils.py#L169-L205)). | Tool parsing включается отдельными flags: `--enable-auto-tool-choice`, `--tool-call-parser`, optional `--tool-parser-plugin`, optional `--chat-template`; это parser/structured-output/template layer, не sampling ([Tool Calling docs](https://docs.vllm.ai/en/latest/features/tool_calling/)). Docs прямо говорят, что caller отвечает за defining tools, context и handling tool calls in application logic для Chat Completions ([Tool Calling docs](https://docs.vllm.ai/en/latest/features/tool_calling/)). vLLM также имеет `repetition_detection` для n-gram loops в raw output ([chat protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/chat_completion/protocol.py#L501-L508), [sampling params](https://github.com/vllm-project/vllm/blob/main/vllm/sampling_params.py#L360-L366)), но это не заменяет breaker одинаковых законных tool calls между agent turns. Responses API имеет `max_tool_calls` в protocol, то есть server-owned tool loops могут иметь отдельный loop limit ([responses protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/openai/responses/protocol.py#L136-L184)). |
