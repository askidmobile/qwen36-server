# QAMQ-A: mixed K-quant recipes и полный A/B на yttri-win

Дата: 2026-10-11.
Задача: T-010. Phase 0: [2026-10-11-qamq-phase0.md](2026-10-11-qamq-phase0.md).
Статус: Phase 1 завершена. Лучший рецепт — **QAMQ-A3**, gate пройден.

## Цель

Собрать mixed K-quant рецепт для Qwen3.5-9B и провести A/B против `unsloth/Qwen3.5-9B-MTP-GGUF/Qwen3.5-9B-Q4_K_M.gguf`:
decode, prefill, VRAM, MTP acceptance и PPL на held-out наборе.

## Рецепты

### QAMQ-A (консервативный)
- SSM-параметры F32, `ssm_out` Q6_K, attention Q5_K, ffn_down Q5_K, ffn_gate/up Q3_K, embeddings/output Q6_K.
- Dry-run: **5562.07 MiB (5.07 BPW)**.
- Экономия относительно Q4_K_M (~5596 MiB) — **~0.6%**.
- Решение: не собирать, слишком много upcast и почти нет выигрыша. Файл: `qamq-a-tensor-types.txt`.

### QAMQ-A2 (агрессивный)
- Attention q/k/qkv/gate/output Q4_K; ffn_down Q4_K; ffn_gate/up Q3_K; `ssm_out` Q5_K; token_embd Q5_K; output Q6_K; слои 29–31 Q5/Q6; SSM-параметры F32.
- Dry-run: **5022.49 MiB (4.58 BPW)**.
- Собранный файл: `Qwen3.5-9B-QAMQ-A2.gguf`, 5 277 430 176 байт, quantize time 125.5 s.
- Файл: `qamq-a2-tensor-types.txt`.

### QAMQ-A3 (лучший)
- Attention q/k/qkv/gate/output Q4_K; ffn_down Q4_K; ffn_gate/up **Q4_K** (Q3_K убран); `ssm_out` Q5_K; token_embd **Q4_K**; output **Q5_K**; слои 29–31 Q5/Q6; SSM-параметры F32; MTP `nextn.eh_proj` Q8_0.
- Dry-run: **5193.16 MiB (4.74 BPW)**.
- Собранный файл: `Qwen3.5-9B-QAMQ-A3.gguf`, 5 456 392 608 байт, sha256 `91970A42BFA2ACFA6D27E512DB9CD4F6394CD3A899A8B25687B67BB28050B51A`, quantize time 159.5 s.
- Файл: `qamq-a3-tensor-types.txt`.

## Что провалилось

- **QAMQ-A (консервативный)**: dry-run 5562 MiB, экономия 0.6%. Слишком много тензоров поднято в Q5/Q6; смысла собирать нет.
- **QAMQ-A2**: файл на 10% меньше, но decode **медленнее** Q4_K_M и в нашем движке, и в llama.cpp; PPL хуже на 4.0%. Причина — Q3_K/смешанный MMV путь на этой GPU неэффективен. Меньший размер ≠ быстрее.
- **`llama-imatrix --nextn`**: падает на state embedding для Qwen3.5 MTP. MTP head пока квантизуется вручную (Q8_0/F32).

## Что получилось

- Рабочий pipeline: калибровка → imatrix → `--tensor-type-file` → dry-run → build → A/B → PPL.
- **QAMQ-A3**: decode 58.5 t/s (+8.9%), prefill +14.7%, VRAM −355 MiB, PPL +0.59%. Это первый рецепт, который реально быстрее Q4_K_M при приемлемом качестве.
- Подтверждено, что ключ — не «просто меньше бит», а **сочетание эффективного типа (Q4_K) и per-tensor политики**; Q3_K без быстрого ядра только вредит.

## Gate Phase 1

- Decode ≥58 t/s: **выполнен** (58.50–58.57).
- Качество не хуже Q4_K_M: **выполнен с оговоркой** (+0.59% PPL; нужны task evals).
- MTP acceptance: **80–85%** для A3 W1.
- MTP=1 всё ещё медленнее MTP=0: следующий рычаг — overhead MTP, не квантизация.

## Следующие шаги

1. **QAMQ-A3 становится baseline** для дальнейших итераций.
2. Phase 2: rotation/AWQ/low-rank + W4; цель — ещё −10% bytes без роста PPL.
3. Phase 3: DeltaNet/SSM state, KV и MTP head:
   - state: 8-bit per-tensor + Hadamard output;
   - KV: per-channel K / per-token V, pre-RoPE;
   - MTP head: Q8/Q6 + shortlist/two-stage.
4. Настроить task evals (MMLU/GSM8K/HumanEval/MBPP, RU, tool-calling) для A3.
5. Пересобрать imatrix на BF16 и сравнить KLD к BF16 reference.

Выводы:

структурных изменений** (rotation/AWQ дают качество при том же размере, не скорость;
скорость уже на bandwidth-пределе). Настоящий рычаг — Phase 3 (KV/state) или MTP-overhead.
