### 4. Sensitivity map

`llama-imatrix --show-statistics` дал per-tensor и per-layer статистику. Ключевые наблюдения:

- **Последние слои наиболее чувствительные.**
  - `blk.31` layer statistics: `∑E[A²]=62501`, Gain `1.32`, L2 `92.46`, CosSim `0.5930`.
  - `blk.30`: L2 `50.86`, CosSim `0.8726`.
  - `blk.29`: L2 `40.70`, CosSim `0.9105`.
- **`ffn_down` в последних слоях критичен.**
  - `blk.31.ffn_down`: L2 `31418.45`, CosSim `0.0063`.
  - Для сравнения, большинство ffn_down в средних слоях имеют CosSim >0.9.
- **`attn_output` в последних full-attention слоях чувствителен.**
  - `blk.31.attn_output`: L2 `3753`, CosSim `0.0684`.
- **SSM-параметры и output-активации имеют high kurtosis/outlier-сигнал**, что согласуется с литературой по SSM/Quamba.
- Даже в исходном `Q4_K_M` Unsloth-файл уже mixed: SSM-параметры F32, `ssm_out` Q5_K, часть attention V/ffn_down Q6_K, MTP `nextn.eh_proj` Q8_0. Это подтверждает необходимость per-tensor политики.

Полный лог: `D:\Projects\yttri-inference\logs\qamq-imatrix-stats.log`.

## Что не получилось

- `llama-imatrix --nextn` на Qwen3.5 MTP падает на state embedding. Нужен либо фикс llama.cpp, либо отдельный сбор статистики MTP-слоя, либо ручная политика для MTP head.
- Imatrix собран на Q4_K_M, а не на BF16. Для следующей итерации нужно пересобрать на BF16 (возможно, с partial offload).
- Task evals (MMLU/GSM8K/HumanEval/RU) на Phase 0 ещё не настроены; сейчас есть PPL на held-out.

## Выводы для Phase 1

- Нельзя квантизовать всё одинаково: last layers, ffn_down, attn_output и SSM-параметры требуют более высокой точности.
- Не стоит использовать Q3_K без быстрого Q3_K-ядра: Phase 1 показал, что меньший размер сам по себе не даёт ускорения.
- Наиболее перспективный первый рецепт: Q4_K для основной массы, Q5_K/Q6_K для sensitive-тензоров последних слоёв, F32 для SSM-параметров и норм, Q8_0/F32 для MTP head.
- MTP head можно пока оставить Q8_0/F32 без imatrix: он мал, а его acceptance проверяется отдельно.
