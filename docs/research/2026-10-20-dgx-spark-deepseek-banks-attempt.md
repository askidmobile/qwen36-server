# V4.1 на DGX Spark: попытка включить банки и ограничить контекст

Дата: 2026-10-20. Продолжение
[отчёта о 40 tok/s](2026-10-20-dgx-spark-deepseek-40tok-achieved.md).

## Итог

| Что | Результат |
|---|---|
| `DS41_CTX_CAP` (ограничить контекст) | **работает**: 1M → 128K/256K применяется |
| Банки для V4.1 (`--max-seqs 4`) | **core dump** при инициализации |
| Предел очереди | 32 одновременных запроса проходят, но последовательно |

## 1. Ограничение контекста: сделано

Патч в двух местах `ds4-server-rs.rs` — обе ветки, где контекст попадает в
конфиг (ранняя `wire.ctx` и поздняя `v41_ctx_capped()`):

```bash
DS41_CTX_CAP=131072 ./ds4-server ...
# requested: ctx=131072 -> effective: ctx=131072
```

Зачем: `v41_state` аллоцирует KV/компрессор-плоскости от контекста.

| Контекст | На банк | 4 банка | Веса + 4 банка | Запас от 121 ГиБ |
|---:|---:|---:|---:|---:|
| 1M | 5.07 GiB | 20.3 | 126.1 | −5.1 |
| 256K | 1.90 GiB | 7.60 | 113.4 | 7.65 |
| **128K** | **1.37 GiB** | **5.49** | **111.2** | **9.76** |

Считано по `v41_bytes_rows`/`v41_alloc_attn_cache` из самого движка.

Оговорка: цифры «запас» — арифметика от `MemTotal`. Фактический
`MemAvailable` после загрузки модели — 3.0–5.0 ГиБ, потому что веса
резидентны в unified memory и не видны в RSS процесса. Поэтому 4 банка
при 128K — на грани даже по расчёту.

## 2. Банки: почему не получилось

Снял план-отказ (`BankLane::Serial` → `Persistent` под
`DS41_BANKS_EXPERIMENTAL=1`) и прогнал `--check-config`:

```
ctx=131072 seqs=4: "banks":"persistent" "max_seqs":4 quote_overflow
```

`banks_unsupported` ушёл, но запуск с 4 банками падает:

```
ds4-server-rs: V4.1 route: ctx=131072 MTP=off verify=0 prefix_reuse=exact
timeout: the monitored command dumped core
```

Причина архитектурная, не в конфигурации. V4.1 обслуживается
`ds4_bridge_v41_generate` → `ds4_engine_v41_generate_argmax`, внутри
которого:

```c
ds4_v41_state st;                       // ОДИН стековый стейт на запрос
if (!v41_state_alloc(&st, cap, ctx, ...)) return 1;
```

Банки живут в другом слое — `ds4_batch_ctx` + `family_banked_engine_continuous_generate`,
где `ctx->qwen`, `ctx->glm53` и прочие семейства имеют свои ветки. У V4.1
такой ветки нет: `git show origin/main:ds4.c | grep -c "v41.*bank"` → 0,
и в upstream тоже не появилось.

Плюс два побочных эффекта, видимых уже в конфиге:

```
effective: max_seqs=4 mtp=off weights=false
```

- **MTP выключился**: с 4 банками движок отказывает `--mtp-mode on`
  («MTP on requires --mtp PATH»), потому что встроенный драфтер
  однопользовательский.
- **`weights=false`**: отложенная загрузка весов отключилась.

То есть даже если бы инициализация прошла, спекуляция — источник 40+ tok/s —
на банках не работает. Каждый банк получил бы ~27 tok/s.

## 4. Что нужно для настоящих банков

Порядок работ, оценка по коду:

1. `ds4_batch_ctx` для V4.1: member + массивы `v41_state` вместо одного.
   Forward реентерабелен (все `v41_*` принимают `st` указателем, глобалов
   в пути два и оба константны), так что это выполнимо.
2. Пошаговый декод: `v41_forward` уже умеет работать по чанкам, нужен
   обёртка-шаг в общий цикл.
3. Engram feed на банк: сейчас `FeedCore.hist` — общая история.
4. Драфтер на банк либо отказ от спекуляции в банках.

Оценка: **3–5 дней** на банки без спекуляции, больше — со спекуляцией
(в коде прямо сказано: «the cont loop's multiseq forward has an unfixed
race», verify-путь gated single-seq).

## 5. Что осталось включённым

- `DS41_CTX_CAP` — работает, но по умолчанию не задан (контекст 1M).
- `DS41_BANKS_EXPERIMENTAL` — только снимает план-отказ, запуск падает.
  Оставлен как документированный след, не для продакшена.
- Рабочая конфигурация возвращена: `--max-seqs 1 --mtp-mode on`,
  ctx 1M, decode 40–51 tok/s на реальном контенте.

## 6. Наблюдение про длинные ответы

Проверено шесть тестов длиной 1200–16000 токенов (код Тетриса, Змейки,
объяснение тензорных ядер, CFS, платёжная система): **ноль иероглифов,
ноль распада**. Деградации на длинном выводе нет.

Реальная проблема была другая: у reasoner-модели `max_tokens` 16384,
а рассуждения занимали 60–100% лимита, и `content` оставался пустым
(`finish_reason: length`). На тесте с платёжной системой — 67 243 символа
рассуждений и ноль символов ответа. Исправлено: reasoner `max_tokens`
поднят до 32768, чат-модель до 8192, температура 0.7 у обеих.
