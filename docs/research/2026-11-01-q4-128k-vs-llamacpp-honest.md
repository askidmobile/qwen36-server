# Q4_K_M на 128k: честное сравнение yforge и llama.cpp (стенд 2080 Ti)

Дата: 2026-11-01. Стенд `tinycoder.dev`: RTX 2080 Ti 11 ГиБ, **PCIe 3.0 x16**,
2× Xeon E5-2686 v4 (36 ядер / 72 потока), 125 ГиБ RAM.
Модель: `Ornith-1.5-35B-Q4_K_M.gguf` у обоих движков, `ctx=131072`,
`CONTEXT_LIMIT=131072`, temp=0.

## Таблица

| Метрика | llama.cpp (`-ot exps=CPU`, 36 потоков) | yforge (эксперты в RAM через PCIe) | Отношение |
|---|---:|---:|---:|
| Prefill 512 | 214.8 т/с | 196.7 т/с | 0.92× |
| Prefill 4 096 | **440.6** т/с | 280.2 т/с | 0.64× |
| Prefill 16 384 | **604.2** т/с | 322.0 т/с | 0.53× |
| Prefill 32 768 | **683.5** т/с | не снято | — |
| **Декод 128 ток** | **45.75** т/с | 10.3–15.6 т/с | 0.23–0.34× |

Отдельно: новый sm75 prefill-kernel на 131 000 токенах даёт 383.7 т/с
(журнал `2026-10-30-turing-prefill.md`), но при коротких промптах на том же
контексте он проигрывает llama.cpp.

## Почему так — арифметика, а не догадка

Декод 35B-A3B читает **8 активных экспертов × 40 слоёв = 540 МиБ весов на
каждый токен**.

- Чтобы выдать 45 т/с, нужно 540 МиБ × 45 ≈ **24 ГБ/с**.
- PCIe 3.0 x16 физически даёт максимум **15.75 ГБ/с**.
- Значит потолок GPU-пути с экспертами в RAM — около **29 т/с**.
- llama.cpp этих 24 ГБ/с по PCIe не гоняет вообще: он считает экспертов
  на CPU из системной RAM (там полоса ~100+ ГБ/с), а на GPU оставляет
  внимание и плотные слои.

Проверено замерами, а не только расчётом:

- PCIe rx при декоде: **6.2 ГБ/с** (≈78 % теоретического трафика экспертов);
- кэш экспертов в VRAM: hit 93 % запросов, но VRAM покрывает лишь
  **62 из 256 экспертов** на слой (`[moe-audit] table_vram=62 cap=62`);
  кэш 16 МиБ → 10.2 т/с, кэш 4400 МиБ → 15.6 т/с, дальше упирается в VRAM;
- MMA/dp4a-загрузка ядра MoE — 0.04 % пика, то есть ядро ждёт память,
  а не считает;
- `MOE_MMQ_DECODE=1` (тензорные ядра) медленнее MMVQ: 11.35 против 12.9 т/с.

**Вывод: на PCIe 3.0 с Q4 эксперты через GPU ускорить нельзя в принципе.**
Чтобы обогнать llama.cpp на Q4 + 128k/256k, yforge обязан считать
маршрутизируемых экспертов на CPU — так же, как llama.cpp, но с более
быстрым остальным путём (наш prefill-kernel, наши DeltaNet/attention).

## Что нужно сделать, чтобы всё-таки обогнать

Единственный путь: **CPU-путь экспертов в yforge**.
В `moe.rs` уже есть `MoeBackend::Reference` (CPU-исполнение через
`reference_routed_swiglu`), но он требует `ExpertWeights::Packed`
(все эксперты в памяти) и не работает с выгрузкой `Store`.

План:
1. Загружать экспертов как `Packed` на CPU (20.7 ГБ Q4 в 125 ГиБ RAM влезает).
2. Добавить CPU-ядро GEMV для Q4_K (сумма `dp4a` по 36 потокам через rayon).
3. В декоде считать экспертов на CPU параллельно с GPU-путём остальных слоёв.
4. Проверить паритет выдачи и замерить: цель — ≥45 т/с на 128k.

Оценка: 2–3 инженерных дня. Без этого пункта преимущества на Q4 + 128k
не будет ни по prefill на коротких промптах, ни по декоду.
