# Набор сравнительных замеров: yforge ↔ llama.cpp

Скрипты сняты со стенда forge-gpu (`lilah`, 161.104.59.62) и добавлены в
репозиторий 2026-09-19, чтобы сравнение было воспроизводимым. До этого
харнессы жили только в `/root` на сервере.

## Требования

- Сервер `yforge` собирается: `/root/target/release/yforge`
- llama.cpp: `/root/llama.cpp/build/bin/llama-server` (v0.3.0-dev b10375+)
- Модель: `/root/models/Qwen3.8-27B-Q8_0.gguf`
- MTP-голова: `/root/models/mtp.ytf` (только `mtp_bench.py`)
- CUDA_PATH=/usr/local/cuda-12.8 (нужен линковщику при сборке движка)

Все пути захардкожены под layout стенда; при переносе поправить константы
в шапке соответствующего скрипта (`GGUF`, `MTP`, пути к бинарям).

## Скрипты

| скрипт | что меряет |
|---|---|
| `final_verify.py` | **полная сверка в продовой конфигурации**: оба движка с окном 256K; старт→первый токен, установившийся TTFT, префил/декод на 8K/32K/128K/256K, VRAM |
| `prod_full.py` | то же, но без интегральной метрики старта |
| `compare_bench.py` | первый основной протокол: yforge vs llama.cpp по `CTXS` |
| `short_unique.py` | короткий промпт на **уникальных** текстах — выявляет артефакт кеша промпта llama.cpp |
| `total_ttft.py` | интегральная метрика: время от запуска процесса до первого токена |
| `mtp_bench.py` | A/B MTP вкл/выкл на yforge (llama.cpp не умеет ту же голову) |
| `batch_bench.py` | агрегатный throughput и per-request t/s при 4 слотах |
| `prefill_short_parity.py` | короткие контексты + побайтовая проверка greedy-выдачи |
| `clean_vram.py` | парный замер VRAM с настоящим выключателем графов (`CUDA_GRAPHS=0`) |
| `pgraph_cmp.py` | цена префил-графов: скорость и VRAM |
| `peak_vram.py` | пик VRAM при длинной генерации |

## Методика (важные детали)

- Промпты генерируются заново на каждый замер — иначе кеш промпта у llama.cpp
  искажает замер префила (это и стало артефактом «наш TTFT 0.23 против 0.16»).
- TTFT = время до первого токена **включая префил**; токены берутся из
  `usage.completion_tokens`, а не из числа SSE-чанков: при спекуляции один чанк
  несёт несколько токенов.
- VRAM = пик `nvidia-smi` минус фон до старта процесса.
- Готовность сервера проверяется по `/v1/models`; для честного старта
  использовать `total_ttft.py` (часы с момента запуска процесса).
- temp=0, `GEN=65` по умолчанию.

## Типичный прогон

```bash
# полная сверка (продовая конфигурация)
python3 /root/final_verify.py

# короткий промпт, уникальные тексты
python3 /root/short_unique.py

# MTP A/B
CTXS=8192,32768 python3 /root/mtp_bench.py
```

Логи пишутся в `/root/logs/` и остаются на стенде.
